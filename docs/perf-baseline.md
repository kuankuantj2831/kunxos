# KunxOS 显示性能基线（脏区域合成器 + 240Hz 帧时钟）

> 目标：为应用直绘路径接入内核脏区域合成器后的 240 FPS 显示预算建立可量化
> 基线，提供帧率测试报告模板与超预算时的降级方案（`anim::perf_test` 的判定
> 输出引用本文档的降级计划）。

## 1. 测试接入点

- **内核启动期自动化**：`kunxcore/src/main.rs` 在调度器启动前调用
  `anim::perf_test()`（GIC/定时器就绪后、用户态 UI 接管显示前，单核无抢占，
  不与其他路径冲突），输出前缀 `[anim-perf]` 到串口。
- **场景（`kunxcore/src/anim.rs`）**：
  - 0 — 定时器看门狗：CNTP 120Hz → `frame_tick` → `composite` → `present`
    全管线持续推进；
  - A — 局部脏区（320×200 移动矩形，模拟时钟/通知/拖动）经
    `fb_damage` → 脏区拷贝 → `composite` → `present`；
  - B — 整屏脏区（最坏情况：页面切换/整帧重绘），540×960 实测后按像素比
    （×4）线性外推 1080p 预算（纯 CPU 行拷贝/混合是线性带宽瓶颈）；
  - C — 内核覆盖窗口 alpha 混合（Home-Indicator 式 overlay）的合成成本。
- **运行中观察**：shell `perf on|off|stats` 打开/关闭屏幕右上角
  `FPS / CPU% / MEM%` overlay（合成器每帧呈现前绘制，单帧 <1ms），
  `perf stats` 打印累计统计。

## 2. 帧时钟与判定阈值

| 项 | 值 | 说明 |
| --- | --- | --- |
| 帧时钟 | 动画逻辑通道（RISC-V 监督定时器复用），常态 **4.17ms = 240Hz** | 与调度 tick（10ms）解耦；热/低电降档 90/60Hz |
| 每帧预算 | 4.17ms | 240Hz 理论预算 |
| 单帧 render 判定 | p95-render < 4.17ms → “240Hz OK” | 合成+呈现耗时 |
| 验收阈值 | p95 < 12ms | 任务验收线（宽松上界） |
| 掉帧判定 | 帧间隔 > 12ms | 计入 drops 计数 |

无掉帧条件：帧间隔 p95 < 12ms 视为流畅（240Hz 预算内为 4.17ms）。

## 4. 结论与风险

- 540×960 全部场景 p95-render 在 1.5~1.8ms，远低于 8.33ms 预算；整屏脏区
  拷贝约 2MB/1.6ms ≈ 1.26GB/s（内核 ldp-stp memcpy）。
- 1080p 整屏外推 p95 ≈ 7.0ms，恰好落在 8.33ms 预算内（余量狭窄）；这是纯
  拷贝带宽下限，任何额外混合/覆盖/日志开销都会突破预算。

## 5. 降级方案（1080p 纯 CPU 脏区合成超预算时）

按成本从低到高：

1. **脏区合并与钳制**：局部更新合并/相邻矩形归并为包围盒（MAX_DIRTY=32 已
   实现整屏回退）；时钟/文本类小矩形保证单矩形拷贝，CPU 成本与面积成正比。
2. **动态分辨率渲染**：应用按 60~75% 分辨率渲染到自身 back buffer，合成器
   放大到 1080p 扫描输出（最近邻/双线性由内核合成路径完成）。像素带宽
   降低到 ~1.1~2.1MB/帧，渲染成本随面积平方下降。
3. **部分合成器回退**：脏矩形数 > 阈值（如 8）且总脏面积 > 屏面积 50% 时
   退化为整屏单矩形拷贝（一次 memcpy 优于多次零散矩形）+ 脏区 clean；把
   最坏情况固定为有序的整屏拷贝，避免碎片化拷贝开销不可预测。
4. **帧率阶梯**：120Hz → 90Hz → 60Hz（CNTP 周期 11.1ms / 16.67ms），在
   1080p 上保持 p95 < 帧预算；60Hz 预算 16.67ms，纯 CPU 整屏有 2.4 倍余量。
5. **NEON 宽通道**：`ldp/stp`（16B/迭代）升级到 `ld4/st4` 或 `fmov`+NEON
   （128B/迭代）与 `dccvap` 直写（跳过 D-cache 写回），拷贝带宽可再提高
   2~4 倍；仅需修改内核 `memcpy` 的 hot path，所有调用方自动受益。
6. **区域级 HW 加速（未来）**：virtio-gpu/DRM scanout 由设备端 DMA，内核
   只提交脏区列表；当前 ramfb 每帧必须完整写回整屏扫描缓冲（缓存行 clean
   或整帧），此项不做（约束：不引入 GPU 驱动）。
7. **光标 overlay 保持小脏区**：光标移动只提交 26×26 脏矩形（恢复旧位 →
   备份新位 → 画光标 → `fb_damage_present`，贴图 24×24 + 1px 边距），是
   当前唯一有效的区域级优化，任何降级策略下都必须保留。
