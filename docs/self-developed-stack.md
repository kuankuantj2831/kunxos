# 自研替换进度

目标：逐层替换运行时中的外部实现；本地修改的第三方代码仍按第三方统计。
采用标准协议、文件格式和算法不影响实现自研的判断。
当前记录依据源码与目标平台依赖树，不代表所有硬件和功能已经可用。

## 第一层：KOS 哈希与校验（2026-11-15）

已完成代码替换：

- SHA-256 复用 `kunxsec::sha256`，删除 `sha2` 运行依赖。
- CRC-32 在 `kunxsec` 提供表驱动增量接口，删除 `crc32fast` 运行依赖。
  磁盘 CRC 字段仍按原语义跳过，不是用零字节替代。
- BLAKE3-256 实现无密钥压缩、chunk、二叉树与根输出，删除 `blake3` 运行依赖。
  只实现 KOS 接口需要的摘要，不提供 keyed hash、derive key 或任意长度 XOF。
- 更新 KOS 与内核锁文件，保留 `sign` feature 的签名功能开关。

KOS 的普通依赖现在只有项目内的 `kunxsec`。这不表示 Rust `core` / `alloc`
已经替换；开发基准仍使用第三方 Criterion，属于宿主测试工具。

验证：

- 替换前保存的 37 组摘要样本覆盖 64 字节压缩块、1024 字节 chunk、
  平衡/非平衡树、SHA 填充边界，以及 1 MiB 输入。
- 旧实现生成的磁盘可挂载、读写、重新挂载；新生成的 256 块磁盘逐字节一致。
- 临时、独立的宿主对照程序用旧上游库验证了 512 组伪随机输入的三种算法。
  对照程序位于系统临时目录；运行库和正式测试无需链接这些旧库。
- `kunxsec` 40 项测试通过。
- KOS 回归除 `sparse_2tb_volume` 外全部通过，含新增兼容性测试与文档测试。
  2TB 测试在 Windows 创建文件时返回错误 112（磁盘空间不足），未进入 KOS
  格式化；跳过它后的回归通过，不将该项记录为通过。
- KOS RISC-V `no_std` 检查、内核 RISC-V 检查及 release 编译链接通过。
  本轮未执行 QEMU 启动验证。

测试样本格式及来源见 `kos/tests/data/README.md`。

## 第二层：字体解析和光栅化（2026-11-15）

已新增独立实现 `shared/font`（crate `kunxfont`），并接入内核、25 个字体相关
应用和宿主字体测试。已删除原 `third_party/fontdue` 的 31 个源码与说明文件。

- 自研 cmap 4/12 字符映射、水平度量、TrueType 简单/复合字形解析、二次曲线
  展平与非零环绕抗锯齿填充；支持目前使用的全部系统字体和图标字体。
- 删除 `fontdue` 及其 `ttf-parser`、`hashbrown`、`core_maths`、`libm`、
  `allocator-api2`、`equivalent`、`foldhash` 依赖；内核和原生应用的锁文件已更新。
- 当前内核及原生应用的普通/构建 Cargo 依赖均来自项目内；这不包含 Rust
  官方 `core` / `alloc` / 编译器内建运行支撑，也不表示 rootfs 中的 NetSurf
  等移植产物、字体资产或 OpenSBI 已经替换。
- 不实现 CFF/WOFF/字体集合、可变字体、hinting、复杂文字塑形和彩色字形；
  当前静态 TrueType 字体不需要这些能力。没有通过删除现有字形来缩减替换范围。

验证：

- 7 项自包含测试通过，覆盖实心与空心几何、复合缩放/平移/点对齐、cmap 4/12、
  越界、循环引用、非法字号和 4000 组损坏输入。
- 8 个 rootfs 字体的完整字符映射与上游样本一致。
- 4614 个 12/16/28px 字形样本的水平 advance 一致；独立抗锯齿算法的最坏
  单字形平均灰度差为 6.833/255，位图边界最多相差 1px。测试不声称像素完全一致。
- 两个完整中文字库及两套完整 Phosphor 图标库的全部已映射字形均能解析和渲染。
- 字体共享、克隆及并发调用测试通过；RISC-V `no_std` 检查通过。
- 全部 25 个字体相关应用和内核的 RISC-V release 编译链接通过。
- QEMU ramfb 桌面和三次设置启动/返回动画通过，已检查中文与图标画面。
  三次设置字体初始化耗时分别为 91/40/70ms，记录仅代表这次 TCG 环境。
- QEMU 首次启动向导通过，已检查欢迎页的中文、粗体标题与按钮。

字体库支持边界见 `shared/font/README.md`，样本来源见
`tests/font_startup_host/data/README.md`。测试镜像与向导截图在
`build/font-validation/`，桌面/设置测试报告与截图保存在该目录的 `desktop-results/`。

## 第三层：原生用户态运行支撑（2026-11-15）

新增 `shared/runtime`（crate `kunxrt`），无第三方 crate / libc 依赖，已接入
全部 49 个原生用户态可执行程序（包括新增 `rttest`、init、11 个服务及包管理器）。

- RV64 syscall0–6、errno 解码、argc/argv 入口与栈对齐、无分配 panic 诊断。
  通用程序入口统一为 `kunxrt::entry!()`；恢复菜单保留诊断后停留的行为，
  部分测试程序保留专门的 panic 输出或停留策略。
- 自研 C ABI `memcpy` / `memmove` / `memset` / `memcmp` / `bcmp`，
  使用 64/32 位宽通道优化，无需外部内存函数库。
- 统一替换字体应用、包管理器和 TLS 测试原来的不回收 brk 分配器。
  空闲块按地址排序、拆分、相邻合并；支持 Layout 对齐、释放、扩容及清零。
  堆以至少 256 KiB 的页对齐块增长，释放后留在进程内复用，进程退出时归还系统。
- 堆由进程锁保护，原生 fork 调用经运行库持锁复制并在父子进程中释放锁，
  避免复制到永久锁定的堆状态；应用自己的锁仍须遵守多线程 fork 约束。
- 常用 syscall 汇编封装改为运行库导入；内核、专门的故障注入/系统调用测试、
  个别共享组件中的直接 ecall 仍是项目自有代码，不属于第三方运行库依赖。

验证记录：

- 5 项宿主测试通过：内存拷贝各相对对齐/重叠方向、errno 边界、
  3 万轮随机分配/释放的数据完整性与完全合并、内存耗尽后的数据保留及区域合并。
- 全部 49 个原生程序 RISC-V release 编译链接通过。`rild` 的项目内 C PDU
  实现使用临时 Zig/Clang 宿主工具编译；该工具不进入系统镜像。
- 独立镜像全部使用新编译的原生程序，内核重新内嵌镜像；QEMU 实测
  `rttest`、syscall `probe`、`pkg list` 均正常且退出码为 0。
- `rttest` 覆盖至 64 KiB 对齐、清零/扩容、2 万轮分配释放、fork 后的堆操作，
  连续 100 次字体解析/绘制/释放后映射量稳定为 524288 字节，全部空闲且合并完整。
- QEMU ramfb 桌面及三次设置启动/返回动画通过，已检查中文与图标截图；
  三次设置字体初始化为 23/28/39ms，仅代表此次 TCG 环境。
- QEMU 首次启动向导通过，已检查欢迎页中文、粗体标题与按钮。

可复现脚本 `tools/test_runtime.py`，运行库接口与限制见 `shared/runtime/README.md`。
测试日志、报告和独立镜像位于 `build/runtime-validation/`。

本层完成的是当前原生程序所需的运行支撑，不是完整 C/POSIX 库。Rust 官方
`core` / `alloc` / compiler builtins 尚未替换；现存 NetSurf/musl 产物、OpenSBI
和字体资产也仍需后续处理，不把“Cargo 普通依赖无外部源”当作全系统自研。
