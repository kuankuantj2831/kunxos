# 显示适配与流畅度

目标：同一系统依据设备的屏幕模式、密度和刷新率布局；QEMU 窗口改变尺寸时，
应用重新排版并保留状态。动画在屏幕与设备性能允许的范围内使用最高稳定帧率。

## 当前实现的边界

当前仍是 ramfb 输出，应用绘图缓冲和导航坐标仍固定为 540×960。
**拖动 QEMU 窗口不会触发系统重新排版。** GTK 的窗口缩放不能作为此功能的验收。
本次变更先接入显示能力契约与帧调度，尚未交付完整的动态分辨率适配。

- `shared/display.rs`：版本化的显示信息 ABI、物理像素/密度布局计算、绝对时间
  帧时钟、带迟滞的动画采样精度，以及双线性 XRGB 采样。
- HAL 的 `DisplayInfo` 可携带真实 stride、密度、刷新率和驱动能力；Pi4 保留
  固件返回的 pitch。刷新率为 0 表示未知，不把定时器频率当成屏幕刷新率。
- `/dev/fb0` 的 `0x4604` ioctl 返回 40 字节显示信息，旧的 24 字节 ioctl 保持兼容。
  应用使用小端字段解码，拒绝版本、几何、stride、密度与刷新率异常的响应。
- 桌面与 OOBE 按设备/电源策略给出的目标节奏运行；睡眠扣除绘制耗时，跳过已错过
  的帧，避免累积延迟；输入打断帧等待后重新对齐时钟。
- 桌面恢复/返回转场优先使用逐像素双线性采样，持续超预算后才降至 2px/4px；
  连续有足够余量后逐级恢复。1:1 无淡化的快照直接复制，避免最终画面被块采样。
- 内核正常温度下采用设备支持的节奏；过热和低电量继续限制动画开销。

### 显示信息 ABI

| 字节偏移 | u32 字段 | 含义 |
| --- | --- | --- |
| 0 | version | 当前为 1 |
| 4 | generation | 当前固定 1；后续模式切换提交后递增 |
| 8, 12 | width, height | 当前输出像素尺寸 |
| 16 | stride_bytes | 实际行字节数 |
| 20 | density | 1024 = 1x；dp = pixels × 1024 / density |
| 24 | refresh_millihz | 驱动报告的实际模式刷新率；0 = 未知 |
| 28 | target_millihz | 当前软件帧调度目标，包含设备/温度/电量限制 |
| 32 | capabilities | bit 0 = VSYNC，bit 1 = 动态尺寸；ramfb 均为 0 |
| 36 | reserved | 当前为 0 |

QEMU 可显式传入 `-append "display-hz=144"`，让软件节奏跟随宿主屏幕的已知值。
该参数是宿主提示，不会改变显示器的物理刷新率，也不会令 ramfb 获得 VSYNC。
未知模式且未提供提示时沿用原有约 240Hz 软件目标。

内核 shell 的 `display` 输出模式、stride、密度、实际刷新率、软件目标和能力；
`perf stats` 输出实际呈现统计。目标帧率与实际呈现帧率必须分别报告。

## 动态分辨率后续必须接通的路径

1. **设备后端**：枚举屏幕支持的模式、原生模式、刷新率与密度，提交 modeset，
   接收 hotplug/VSYNC。真机取自对应显示控制器/面板驱动，不能假设所有设备均为
   540×960 或 240Hz。QEMU 必须增加明确的宿主尺寸通知通道或替换显示后端；
   添加 virtio-gpu 本身不等于 GTK 窗口变化会自动到达来宾。
2. **安全模式切换**：合并连续 resize 请求，先分配并验证新 surface，再发布新的
   generation。旧 mmap 在应用停止使用前不能释放。OOM 保留原模式，失败不得发布
   新尺寸。切换同时更新 stride、脏区、触摸坐标与光标范围。
3. **应用运行时**：用可调整的 surface 替换所有固定大小的全屏数组。处理 generation
   变化，重新映射显存、清除尺寸相关缓存，再以 dp 和可用区域计算布局；重新排版
   时保留输入内容、滚动位置、焦点和运行中的应用。不能仅拉伸原来的 540×960 像素。
4. **布局与动画**：导航条、Dock、网格、控制中心、锁屏、OOBE 和内置应用都需迁移；
   文字按目标密度重新栅格化。尺寸变化时从当前动画状态继续，时间用单调时钟，
   动画持续时间不依赖帧计数。先优化脏区与像素搬运，再决定是否降低特效质量。

## 验证

```sh
python tools/test_display.py --qemu /path/to/qemu-system-riscv64
python tools/test_display.py --qemu /path/to/qemu-system-riscv64 --oobe --rate 60
```

测试在临时目录构建独立 rootfs/内核，使用 `KUNX_RAMDISK` 指定内嵌镜像，不覆盖
工作目录里的 rootfs、ramdisk 或 kernel.img，也不重启用户已有的 QEMU。
它运行共享算法测试并启动来宾，核对显示 ioctl 的桌面消费、软件节奏、能力声明与
启动结果。日志、屏幕图像和 JSON 报告保留在测试目录。

完整功能还需通过：竖屏/横屏/宽屏/高密度、多次拖动窗口后布局重排、触摸命中、
旋转/热插拔、模式切换失败与内存回收，以及真实 VSYNC 的设备验证。
目前这些动态分辨率验收项尚未完成；现有测试不证明动态分辨率已经可用。
