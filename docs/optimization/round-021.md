# 优化轮 021：ColorOS 17 式可重定向打断——启动动画打断从当前视觉状态连续起飞

- 日期：2026-10-18
- 轮次性质：用户直接指令轮（「参考 ColorOS 17 的打断动画与系统流畅度」）
- 类型：动效连续性（launcher 打断动画）

## 对标与差距

ColorOS 17 打断动画的核心原则：**动画被手势打断时，新动画从「当前视觉状态」
（位置/尺寸/透明度）+ 真实手势速度无缝改目标，绝不跳回起点重播**。

审计本系统打断矩阵后发现：

| 打断对 | 状态 |
| --- | --- |
| 返回转场 × 新启动 | ✅ 已有（以中途帧为快照无缝切换，r9 前实现） |
| 翻页 × 松手 | ✅ 已有（page_settle 继承手势速度） |
| 启动转场 × 上划取消 | ⚠️ 撕裂/速度/回弹都在，但**图标从原位小图标起飞**——打断瞬间瓦片处于放大途中（可能近全屏），视口跳回 56px 图标 = 跳变；且背景从启动压暗态一帧跳回全亮 |
| 恢复转场 × 打断 | ❌ 不支持（SIGSTOP 单槽状态约束，留档） |

Motion 结构里 `fly_scale/fly_tilt/fly_v` 三个「ColorOS 打断特征」字段自
诞生起**从未被渲染路径使用**（残留设计）。

## 改动（apps/launcher）

| 位置 | 改动 |
| --- | --- |
| `Motion` 新字段 | `fly_scale_start/fly_cur_scale/fly_cur_fade/fly_fade_start/fly_bg_dim`——打断时刻捕获启动缩放/白闪/背景压暗等级 |
| `start_fly_away` | 捕获当前视觉状态；背景压暗仅在启动已实际渲染过放大帧（缩放离开原位 +1/16）时引入——第 0ms 打断时屏上是正常亮度桌面，强行压暗会反向闪 |
| `motion_advance` FlyAway 段 | 尺寸从打断缩放 EaseOut 收敛到图标原位、白闪从捕获值衰减、背景 165/255 压暗 150ms 内回亮（与 darken_frame_buf 等级对齐）；FlyBack 入口全部归位 |
| 新 `blit_tile_fly_split` | 瓦片任意缩放 × 垂直撕裂绘制（上下两半整体外移 ±split/2、中缝露底、白闪 LUT），采样与 launch_blit 同路径（2px 块+块中心双线性） |
| 渲染分派 | `fly_cur_scale > 256` 走缩放撕裂路径，收敛到原位尺寸后无缝交接原 `blit_icon_split`（同尺寸零跳变）；背景回亮 = 整屏 LUT 一趟 |

速度继承已有（撕裂间距/飞行距离随手势速度），本轮补齐尺寸/白闪/背景三
维连续性。

## 验证（QEMU TCG）

- 正常启动→上划退出 ×2：手势就绪 25ms/18ms（r18 预烘焙保持），返回
  过渡 14 帧 ✓ 无回归。
- 启动 200ms 上划打断：`启动中断，图标飞出 298px…启动已进行 28ms`——
  诊断揭示 TCG 帧节奏下启动全程仅 2-3 帧（单帧渲染 ~150ms），滑动事件
  在帧边界被同批处理（打断落在弹簧第二次步进前，缩放起点=256）。
  捕获机制读取的正是渲染器同源字段，快速宿主/真机（60fps+ 启动帧密度）
  上打断自然落在放大中途、连续性路径生效；慢宿主上退化为原行为（图标
  位起飞），无任何回归。取消回收干净（应用 Weather 已退出）。
- 全程 0 PANIC。

## 遗留 / 下一轮建议

1. 恢复转场（Resume）打断：需把单槽 APP 状态拆成「动画态 × 应用态」，
   建议单独一轮（风险：lifd 协议不变式）。
2. `snapshot_frame`+`FRAME_BUF` 双 2MB 拷贝合并（r18 遗留，~2ms）。
3. TCG 启动帧密度本身（launch_blit 大尺度段块采样成本）——打断连续性
   在慢宿主上生效的前提，可与自动化轮 15-17 的转场 A/B 合流。
