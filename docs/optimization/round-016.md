# 优化轮 016：转场隔行混合同开机受控 A/B——判零增益（1.00x）回退全量；发现 OOBE 点击风暴 PANIC

- 日期：2026-10-18
- 轮次性质：自动化第 15 轮（轮号 015 被并发会话用户直指令轮占用，
  其声明避让本会话 oobe/tools 在制品——双向协作正常）
- 类型：性能归因（round-011 方法论首次完整落地）+ 稳定性发现 + 行为回退

## 本轮目标

round-011 立下的规矩「帧率断言必须同一次开机内 A/B」首次完整执行：
给 round-012 收编的隔行混合做严格归因。

## 方法（配对实验设计）

`transition_pages` 增加 `TRANS_AB_TOGGLE` 逐场交替隔行/全量模式，
转场打印带模式标签——**同一次开机、同一宿主状态、相邻转场交替两种
模式**，12 次转场 6:6 配对（boot_trace 放慢点击节奏 0.8s→1.8s/次、
hold 0.12s，绕开下述 PANIC 后完整走完 13 步）。

## 结果与处置

| 模式 | 帧数分布 | 中位 |
| --- | --- | --- |
| 隔行 | [3,4,4,4,4,4] | 4.0 |
| 全量 | [4,4,4,4,5,5] | 4.0 |

**隔行/全量 = 1.00x，零增益** → **回退全量混合**（垂直清晰度不再
支付无收益的代价）；行指针直写（round-009）保留。历史修正：隔行增益
预期（round-011 留树时预估 2x）与 round-009 的「13→26fps 2x」结论
均产生于宿主负载漂移期，后者未经同开机对照复核，列入待验。

推论：**混合并非转场 ~45ms/帧的主导成本**（减半混合量帧数不动）——
真瓶颈在转场循环的其它每帧工作（导航快照恢复/进度点重绘/呈现/插值
数学），需 phase 分解定位（同 round-002 对 fb_present 的做法）。

## 稳定性发现：OOBE 点击风暴 PANIC（高危，下轮首选）

```
PANIC: oobe src/main.rs:4307   ← EV_BUF 压缩循环（EV_LEN-24 前移）
```

复现：0.8s 间隔点击风暴打到「模块」页（第 3 步）必崩；init 兜底拉起
launcher（round-013/14 的「桌面就绪」实为崩溃兜底路径——桌面基线
44.3s 的 OOBE 段含义需按此修正：正常走完为混合快进 5-6 分钟/纯自动
推进约 8 分钟）。线索：日志见**连续两个 input down 无 up**（0xAA 帧
在突发下丢失）→ 内核串口输入帧解析器突发丢帧 + 用户态 EV 缓冲压缩
在异常序列下疑似越界（`rest = EV_LEN - 24` 下溢路径待证）。放慢节奏
（1.8s/次）即消失。本轮已绕开未修，**下轮根因修复**（内核帧解析器 +
用户态防御性门控双查）。
