# 优化轮 009：OOBE 步间转场帧率——13fps→26fps（2x），转场诊断打印固化

- 日期：2026-10-18
- 轮次性质：自动化第 8 轮
- 类型：动画/动效质量（round-005 遗留复核项，复核中发现真短板）

## 本轮目标

复核 OOBE 步间转场（160ms 交叉淡化 + 上滑回弹）是否有 round-005 同款
过时节流。结论：**无节流门**（真实时间推进、帧率拉满模式），但加帧数
诊断后发现真短板——**转场实际只有 2-3 帧 / 160ms ≈ 13fps**，每帧 ~76ms。

## 根因

转场每帧对内容区 ~42.6 万像素逐像素执行：`fb_set_px()` 函数调用 + 边界
检查 + 三通道混合（~25 条 guest 指令/像素），在 TCG 下 ~76ms/帧。此前的
夜间工单把「局部区域动画」（光锥/呼吸）拉到 81fps，但全屏交叉淡化天然
是 40 倍像素量，从未达标。

## 改动点

| 文件:位置 | 改动 |
| --- | --- |
| `apps/oobe/src/main.rs` `transition_pages` 混合路径 | dst 行指针提到行循环外，行内直接指针写（循环边界 x∈[0,W)、y∈[0,ny) 已保证在屏内，免每像素函数调用+边界检查） |
| 同 `ea>=255` 末帧路径 | 整行 `copy_nonoverlapping`（走 memcpy 宽通道）替代逐像素写 |
| 同 导航区尾拷贝 | 逐像素 `fb_set_px` → 整行 `copy_nonoverlapping` |
| 同 | 固化转场诊断：结束时打印 `[oobe] 转场 N 帧 / Xms`（160ms 固定时长 → 帧数即帧率），永久观测点 |

## 验证

### 量化（GUI 实例，OOBE 30s 自动推进，[oobe] 转场打印）

| | 转场帧数（min/中位/max） | 帧率 |
| --- | --- | --- |
| 优化前 | 2 / 2 / 3（n=4） | **~13fps** |
| 优化后 | 4 / 4 / 5（n=5） | **~26fps** |

每帧 ~76ms → ~45ms（1.7x）；剩余主导是混合数学本身（~22 指令/像素 ×
42.6 万像素），进一步提速需结构性手段（见遗留）。

### 构建与 GUI 冒烟

`make kernel` 0 错误。GUI：0 PANIC，OOBE 推进至 6/13，转场后画面像素
统计正常（698 色、行多样性 2-60 结构化、无花屏特征）。截图
/tmp/kunxos-vnc-r9.png。

## 遗留问题 / 下一轮建议（按优先级）

1. **转场混合的深水区**（本轮 2x 后仍是 26fps）：候选手段按性价比——
   ① 混合循环 u64 双像素打包（减半循环开销）；② 打包通道算术（x86 伪
   向量技巧移植 RV64，需借位隔离掩码，正确性风险高须配像素级自检）；
   ③ 降低转场分辨率（perf-baseline §5.2 动态分辨率方案）；④ 转场期间
   只混合奇数行、偶数行上帧结果复用（视觉略降）。预计 ①+④ 可再达 2x。
