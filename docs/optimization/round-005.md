# 优化轮 005：OOBE 空闲动画解锁——移除过时跳帧门，空闲呼吸 51→100fps、尖峰清零

- 日期：2026-10-18
- 轮次性质：自动化第 4 轮
- 类型：动画/动效质量（round-002 遗留的头号候选，顺延两轮后执行）

## 本轮目标

剖析 round-002 观测的「渲染只剩 40µs 但帧间隔 ~19.7ms」：定位应用主循环
节拍瓶颈并消除。

## 根因分析

OOBE 空闲主循环（apps/oobe/src/main.rs 主 loop 无输入分支）每圈：
非阻塞读输入 → 光标/悬停/呼吸动画 → `sleep_ms(8)`。

帧间隔下限来自 `animate_idle` 的**故意隔圈跳帧**（`ANIM_IDLE_SKIP` 翻转，
每 2 圈推进一次呼吸动画）。其注释写明依据：「每帧呼吸……区域呈现是空闲
循环的大头——让出一半循环给光标移动（用户实测移动卡）」。这是合成器
**每帧 1.6-1.8ms 整屏拷贝时代**（round-002 已根治，现 ~40µs/帧）的成本
权衡：跳帧每圈省 ~0.8ms 呈现时间。该依据随 round-002 修复消失，跳帧门
只剩副作用——空闲动画被锁在 2×(8ms sleep + 圈内工作) ≈ 16.5-19.7ms/帧
（≈51fps），且圈间不均匀造成 p95 22-24ms、每统计窗 26-59 个 >20ms 尖峰。

## 改动点

| 文件:位置 | 改动 |
| --- | --- |
| `apps/oobe/src/main.rs` `animate_idle()` | 删除 `ANIM_IDLE_SKIP` 隔圈跳帧（含 static 定义），呼吸动画每循环推进一次；注释更新说明依据变化。空闲 `sleep_ms(8)` 让出 CPU 的节拍与光标每循环处理（主循环 `CURSOR_DIRTY` 快路径）均不变 |
