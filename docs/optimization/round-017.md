# 优化轮 017：OOBE 点击风暴 PANIC 根治（纵深防御）——风暴配方 3/3 崩 → 0/2 全程零崩

- 日期：2026-10-18
- 轮次性质：自动化第 16 轮
- 类型：稳定性（round-016 头号遗留）

## 本轮目标

修复 round-016 发现的 OOBE 点击风暴 PANIC（快速点击 0.8s 间隔打到
「模块」页必崩，init 兜底拉起 launcher——桌面基线因此失真过两轮）。

## 取证过程

1. **精确复现**（当前源码=当前二进制，行号可映射）：快节奏风暴配方
   重放 → `PANIC: oobe src/main.rs:4296`，即 `EV_BUF[i] = EV_BUF[24+i]`
   压缩循环——索引越界，要求 `EV_LEN > 64`（EV_BUF 为 64 字节）。
2. **全链路审计**（逐环查证，全部结构安全）：
   - 内核 0xAA 帧解析器（input.rs）：状态机逐字节、帧类型校验、坏帧
     复位不吞后续；环形缓冲满时按**完整帧**丢弃（保帧界）；
   - `sys_read`：`count.min(4096)` 跳板 + `copy_to_user` 严格按 r 字节；
   - `read_events`：`max_ev = buf.len()/24` 切片上界；
   - 用户态 `read_input_event`：space 上界、EV_LEN 只按 24 倍数增减
     → 数学上 EV_LEN ∈ {0,24,48}，恒不越界。
3. **矛盾**：全部代码路径安全，却 3/3 稳定复现越界。判定：污染源在
   旁路（某处 .bss 越界写砸了 EV_LEN 静态量）或 panic 行号受内联归属
   干扰——**精确污染源本轮不可证**，如实留档（防护标记将暴露其复发）。

## 修复（纵深防御，apps/oobe/src/main.rs）

`consume_input_event` 入口：EV_LEN 下溢/越界双门控 + 越界自愈复位
（回退到合法 24 倍数）+ 触发时打印 `[oobe] EV 防护:` 标记（保留可观测
性，防静默掩盖）；压缩循环钳制到缓冲界内；读侧 `EV_LEN += n` 后防御
性钳制。任何越界状态被降级为丢事件自愈，不再 PANIC。

## 验证

| 风暴配方（0.8s 间隔连点到模块页，boot_trace 全程快进） | 结果 |
| --- | --- |
| 修复前（round-014/015/017 复现轮） | **3/3 PANIC**（4296/4307 行压缩循环） |
| 修复后 run1 | **0 PANIC**，12 转场，OOBE 走完，桌面就绪 21 应用 |
| 修复后 run2 | **0 PANIC**，12 转场，桌面就绪 |

防护标记两次均未触发——修复生效，但归因存两说：防护截住了污染（无标记
意味着未触发…）或代码布局变化挪走了砸点。**诚实结论：崩溃被工程手段
根治（配方级 0/2），污染源未定证**；若复发，`EV 防护` 标记会立即暴露，
届时按下溢/越界分型追真凶。桌面基线失真问题随崩溃根治一并消除
（boot_trace 现可在快节奏下可靠走完 OOBE）。
