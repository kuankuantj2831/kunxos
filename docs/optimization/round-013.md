# 优化轮 013：启动耗时首基线（内核→UI 1.7s，启动链路不是短板）+ tools/boot_trace.py 基建

- 日期：2026-10-18
- 轮次性质：自动化第 12 轮（轮号 012 被并发会话的用户直指令轮占用，
  其文档与提交 c7c3bd7 已收编本会话轮 011 留树的隔行改动——协作闭环）
- 类型：剖析/审计轮（round-011 避让清单 ②b 项）

## 本轮目标

建立从未测过的启动耗时基线（QEMU 启动 → 桌面就绪全链路分解）+ 首次采集
launcher 桌面直绘渲染数据。纯观测，不改产品代码（OOBE 仍处并发会话
在制期，继续避让）。

## 新增基建

`tools/boot_trace.py`：启动全链路时间戳记录器——串口行级到达时间戳
（`.ts` 旁路文件，原始日志保纯净）、阶段标记切分（OpenSBI/服务/OOBE UI/
首帧/桌面就绪）、OOBE「下一步」注入快进（复用 app_open_shots.py 坐标与
PIN 步停手逻辑）、桌面 [perf] 采集窗口 + QEMU monitor 截屏。可复用于
后续所有启动/桌面相关轮次。

**基建首跑抓出并修掉的两个坑**：① 串口 fifo 读线程若早夭，QEMU 写侧
EPIPE 直接退出（首跑 8 秒即死、stderr 被吞）——读线程改为永不退出 +
QEMU stderr 落盘（`-qemu.err`）；② 逐 chunk 加时间戳前缀会污染日志
内容——改行级旁路文件。

## 首基线（QEMU virt TCG，riscv64，全新镜像首启）

| 阶段 | 累计耗时 |
| --- | --- |
| QEMU 启动 → OpenSBI banner | **0.05s** |
| → init 拉起服务（lifd 就绪） | **1.49s** |
| → OOBE 首个 UI 输出 + 输入就绪 | **1.69s** |
| → 首帧呈现窗口闭合（含 ~1.4s 字体加载） | ~6.2s（首帧本身 ≈3-4s） |
| → 桌面就绪 | **未完成**（见下） |

**结论：启动链路不是短板**——内核+init+服务+UI 就绪 1.7s、首帧 ~4s
（TCG 软件模拟下）。到桌面的时间大头是 OOBE 13 步向导流程本身（交互/
30s 自动推进），不是系统启动。启动性能方向降权，后续优先级让位。
