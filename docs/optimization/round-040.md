## 机制修正（r39 假设再修正）

读 mbx_writer 实证：写者是**每条 open(O_APPEND)→write→close**（非长命
fd，r39 记错）。真实丢失窗：写者 open 抢在读者 rename(pipe→taken) 之前
→ write 落在 taken 的 inode 上但晚于读者 read_all → 写者 close →
unlink(taken) 此时**必然成功**（无 fd 持有）→ 该条消息（可能是 DONE
哨兵）永久删除 → dones 冻结。TAKEN_LEFT「持 fd 时 unlink 失败」防御对
每条开关的写者完全无效。

## 新协议（apps/sfsrace/src/main.rs 重写 mbx_reader）

1. **认领名单调递增**：rename(pipe → mbx.pipe.r_k)（k 不复用）——
   rename 原子、fd 随 inode，迟到写落在留档文件里**不丢**；
2. **运行中不删除本轮/上轮留档**：**两轮隔离删除**（每轮删 k-2）——
   迟到 fd µs 级寿命 vs 跨两整轮认领（ms 级），残留概率天文低；
   （首版「永不删除」被根卷 512 inode 教育了：写者 iter~25 即 ENOSPC，
   0/5 实测——隔离删除兼顾卫生与安全）；
3. **终局扫排**：dones==WRITERS 且取空后，重读最近 3 份留档兜住全部
   非哨兵迟到者（哨兵是写者最后一条，哨兵齐 ⟹ 无人再写），再清理。
