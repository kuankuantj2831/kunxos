# 优化轮 051：内核输入丢弃计数器落地——把 r50 一级丢弃从推断变成可测量

- 日期：2026-10-20
- 轮次性质：自动化第 50 轮
- 类型：可观测性基建（r50 链路未闭合部分的武器）

## 反转发现（先读代码再动手的直接收益）

r50 的「pulse 动画期不读输入导致环形溢丢」假设被代码推翻：
`pulse_selection` 循环**本就调用 pump_input_during_anim**——但 pump 按
设计「读走并丢弃点击动作」（保光标移动）。故二级丢失确认为设计内；
**一级丢失（52 发 → 8 达应用）仍未定证**——OOBE 侧 down 日志即 pump
也打（8 条），说明 44 次点按的事件从未离开内核输入路径，机制待测。

## 本轮交付（kunxcore/src/input.rs + perf.rs）

环形缓冲两条丢弃路径分别计数：
- `EV_DROPPED_MOVE`：移动帧合并丢弃（无损语义，光标位置类）；
- `EV_DROPPED_FULL`：全满整帧丢弃（**真实丢失**，r50 一级丢弃点）；
- `perf stats` / shell 输出 `[perf] input丢弃: 合并=N 全满=M`。

下次任何采集轮复跑注入风暴即可直接读数定证一级丢失机制（全满？
还是事件根本未入环？计数为 0 则矛头转向注入链路本身）。

## 验证

- 构建 0 错误；lifecycle-core **38/38**；GUI 冒烟 0 PANIC、OOBE 正常
  （计数器零开销路径：仅丢弃时累加，读取 O(1)）。
