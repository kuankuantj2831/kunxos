# SFS v2：掉电安全 + 磨损均衡 + 大文件支持设计

本文档是 SFS v2 的完整设计说明与磁盘格式规范，实现于 `kunxcore/src/fs_simple.rs`
（内核）与 `tools/mkfs_sfs.py`（宿主打包工具），两者必须严格一致。

## 1. 背景与目标

SFS v1（当前实现）的已知问题（见 `docs/sfs-audit.md`）：

- **无掉电保护**：truncate 先释放位图后写 inode、rename 非原子、无 fsync；
  崩溃后元数据可能撕裂（inode 引用已释放块、目录项与 inode 不一致）。
- **无磨损均衡**：first-fit 从位 0 扫描，位图块 / inode 表是高频擦写热点；
  256MB 数据分区下位图块（4KB）每次分配都写，SD/eMMC 10K-100K 次寿命
  很快耗尽。
- **单文件上限 ≈4.2MB**：size 为 u32，24 直接 + 单间接 1024 块。
- **无校验和 / 无双超级块 / 无 fsck**。
- 数据位图单块只能覆盖 128MB（32768 块 × 4KB），256MB 分区浪费一半。

SFS v2 目标：写前日志（WAL）元数据事务、挂载时崩溃恢复、fsync 语义、
磨损感知分配、64 位文件大小（间接块多级，单文件 ≈4TB 上限）、双超级块 +
CRC32、fsck 一致性检查。**不引入 ext4/f2fs，保持自研。**

## 2. 磁盘布局 v2（块大小 4KB，块号从 0 开始）

```
块 0               超级块（主）
块 1               超级块（备份）
块 2               inode 位图（128 位，1 块）
块 3..3+B-1        数据位图（B = ceil(数据块数 / 32768)，多块）
块 3+B..3+B+7      inode 表（128 × 256B = 8 块）
块 3+B+8..+J-1     日志环（J = min(1024, max(64, total/8)) 块）
块 DATA_START..    数据区
```

区域边界全部写入超级块（`bmap_start / inode_start / jlog_start / data_start`），
布局可随分区大小伸缩。`B` 与 `DATA_START` 存在循环依赖，用定点迭代求解
（1-2 轮收敛）。

典型值：

| 分区 | total | J（日志） | B（数据位图） | DATA_START | 可用数据 |
|------|-------|-----------|---------------|------------|----------|
| /data（256MB） | 65536 | 1024（4MB） | 2 | 1037 | 64499 块 ≈ 252MB |
| rootfs（128MB 分区） | 32768 | 1024 | 1 | 1036 | 31732 块 |
| ramdisk（6MB） | 1536 | 192 | 1 | 204 | 1332 块 |

**块大小保持 4KB**：与 SD/eMMC 擦除块（典型 512KB）不对齐，但改动块大小
会推翻整个设计且与既有镜像不兼容；日志区与位图的磨损已由环形日志 + 检查点
批量刷盘大幅缓解（见 §6）。对齐问题在 §10 记录为已知限制与后续工作。

## 3. 超级块（块 0 / 块 1，各 4096 字节）

主/备两份内容相同；写入顺序**先备份后主**（备份写失败时主仍是旧但完整可用的
副本；主写失败时备份是新副本）。挂载时先读主，CRC 或魔数失效则回退备份。

```
@0   u32 magic    = 0x5F534632  ("_SF2")
@4   u32 version  = 2
@8   u32 blk_size = 4096
@12  u32 total_blocks
@16  u32 inode_blocks = 8
@20  u32 bmap_start = 3
@24  u32 bmap_blocks
@28  u32 inode_start
@32  u32 jlog_start
@36  u32 jlog_blocks
@40  u32 data_start
@44  u32 num_inodes = 128
@48  u32 root_ino = 1
@52  u32 free_inodes      （检查点时的值；运行期以 RAM 为准）
@56  u32 free_blocks      （同上）
@60  u32 flags            （bit0=needs_recovery，信息性）
@64  u64 jlog_head_seq    （环内最旧未检查点记录的事务序号）
@72  u64 jlog_head_abs    （环内最旧未检查点记录的绝对位置）
@80  u64 jlog_next_abs    （下一记录写入位置）
@88  u32 ino_hint         （轮转 inode 分配提示）
@92  u32 blk_hint         （轮转数据块分配提示）
@96  u32 crc              （crc32(bytes[0..96])）
@100..4096 保留（清零）
```

超级块只在 **mkfs / 检查点 / 恢复完成** 时写入 —— 每次事务提交不写超级块，
避免超级块成为新热点。

## 4. inode v2（256 字节，表内 128 个）

```
@0   u16 type   （T_REG=1 T_DIR=2 T_CHR=3 T_BLK=4 T_FIFO=5 T_SYM=6）
@2   u16 nlink
@4   u64 size   （64 位文件大小）
@12  u32 rdev
@16  u32 gen    （分配世代号，释放+1，防陈旧引用误用）
@20  u32 crc    （crc32(bytes[0..256])，crc 字段本身按 0 计算）
@24  u32 direct[24]        （24 个直接块号 → 24×4=96B，到 @119）
@120 u32 indirect          （单间接：1024 块指针 = 4MB）
@124 u32 double            （双间接：1024² 块 = 4GB）
@128 u32 triple            （三间接：1024³ 块 ≈ 4TB）
@132 u32 uid      （所有者；仅 @142 bit0 置位时有效）
@136 u32 gid      （所属组）
@140 u16 mode     （权限位 rwxrwxrwx）
@142 u16 ownflags （bit0 = 归属元数据有效；0 = 无归属，行为同旧版）
@144..255 保留（清零）
```

逻辑块号映射：

```
logical < 24                      → direct[logical]
logical < 24+1024                 → indirect[logical-24]
logical < 24+1024+1024²           → double[l1][l2]
logical < 24+1024+1024²+1024³     → triple[l1][l2][l3]
```

单文件上限 ≈ 4.4TB，size 为 u64 —— 突破 4GB 限制。间接块（含中间层块）
属于元数据，写入走日志。空洞（未分配指针）读作全零，天然支持稀疏大文件。

## 5. 写前日志（WAL）—— 环形日志区

### 5.1 记录格式（每条记录 2 个环块：头块 + 数据块）

头块：

```
@0   u32 magic   = 0x5346534A  ("SFSJ")
@4   u32 seq_lo
@8   u32 seq_hi                （seq = u64，事务序号，全局单调，从不回绕）
@12  u32 target                （被修补的块号）
@16  u32 crc                   （crc32(头[0..16] + 数据块[0..4096])；COMMIT 只含头）
@20  u32 flags                 （1=DATA，2=COMMIT）
@24..4095 保留（清零）
```

数据块：被修补块的完整 4096 字节镜像（DATA 记录）；COMMIT 无数据块。

### 5.2 事务协议

每个改变元数据的顶层操作（create / mkdir / symlink / write / truncate /
unlink / rename）是一个事务：

1. **begin**：打开事务，清空待写缓冲。
2. **stage**：所有元数据块修改（位图、inode 表块、间接块、目录数据块）
   先在 RAM 中记录「块号 + 新镜像」（同块多次修改只保留最终镜像）；
   数据块内容（普通文件正文、新块清零）**直接写盘，不经过日志**。
3. **commit**：
   a. 把全部待写镜像作为 DATA 记录（同一 seq）写入日志环；
   b. 写入 COMMIT 标记（同 seq）；
   c. **copy-out**：把非位图镜像写回真实位置（inode 表 / 间接 / 目录块）；
      位图镜像**不**写回（保持 RAM 权威，检查点时批量刷盘）；
   d. 若环即将写满 → 触发检查点。

### 5.3 崩溃安全不变量（同步块设备天然保证顺序）

- 数据块内容写入 **先于** 引用它的元数据提交 → 恢复后任何被引用的块
  要么有效、要么引用尚不存在。
- 所有 DATA 记录 **先于** COMMIT 标记 → 只有带有效 COMMIT 的事务才会被恢复。
- copy-out **晚于** COMMIT → 崩溃于 copy-out 中途时，恢复重放幂等。
- 检查点（位图刷盘 + 超级块 head 前进）**晚于** 全部 copy-out。

### 5.4 检查点（checkpoint）

触发：`fsync` / `sync` / 日志环写满 / 卸载。

1. 把 RAM 位图（inode + 数据）写回磁盘位图块；
2. 更新超级块：free 计数、分配提示、`jlog_head_abs = jlog_next_abs`、
   `jlog_head_seq = 最后提交序号`；先写备份超级块再写主超级块；
3. 设备 flush（virtio-blk FLUSH）。

之后环区 [head, next) 为空（新记录从 head 处覆盖旧记录）。
位图块从「每次分配写 1 次」降为「每个检查点周期写 1 次」，写放大降低约
一个数量级（环满一次 = 约 512 个事务）。

### 5.5 日志写爆防护

- 环容量 = J/2 条 DATA 记录（J=1024 → 512 条），事务记录数 ≤ 24（缓冲上限），
  写前检查 `used + k ≤ J`，不足则先检查点再写。
- 记录跨环尾时先检查点并跳到环首，**禁止记录跨越环尾**（保证 [head,next)
  连续可扫）。
- 元数据不记录文件正文，日志写量 = 元数据量（远小于数据量），且分散在
  J 个块上 → 日志区不会成为擦写瓶颈（每块每周期写 1 次 ≈ 数据区的平均写）。

## 6. 挂载与崩溃恢复

```
mount(major):
  1. 读超级块（主 → 备回退，CRC 校验）
  2. 读位图到 RAM
  3. journal_recover():
     从 jlog_head_abs 起扫描整个环（≤ J 块）：
       - 魔数非法        → 停止（撕裂/未写）
       - seq < head_seq  → 跳过（上个周期的陈旧记录，已检查点）
       - DATA 且 CRC 有效 → 收集 (seq, target, 镜像)
       - COMMIT 且 CRC 有效 → max_commit = max(max_commit, seq)
     重放所有 seq ≤ max_commit 的 DATA 记录到真实位置（幂等）
     若重放了 N>0 条：打印 "journal recovery: replayed N records"
  4. 复位日志：head = next = 0（绝对位置），head_seq = max_commit；
     写超级块（主+备）
  5. 重新加载位图到 RAM
```

正确性要点：

- 未提交（无 COMMIT 或 COMMIT 撕裂）的事务整体丢弃 —— 其元数据从未生效；
- 已提交事务在 copy-out 前崩溃 → 重放补齐；copy-out 后崩溃 → 重放幂等；
- 陈旧记录按 seq 过滤，不参与重放；seq 单调不回绕，杜绝新旧混淆；
- 撕裂写（CRC 失败）中止扫描，只回放其前的完整提交，绝不部分应用一个事务。

## 7. 磨损均衡

v1 的痛点：位图块 / inode 表固定区域高频写。v2 措施：

1. **位图 RAM 权威 + 检查点批量刷盘**：位图块每检查点周期写 1 次
   （环满一次 ≈ 512 事务），热点写放大降约 512×。
2. **轮转分配**：数据块与 inode 都从持久化提示位（`blk_hint` / `ino_hint`）
   开始 next-fit 扫描，分配与释放都推进提示位 → 新数据散布全盘，避免
   低位块反复复用；提示位随检查点持久化，恢复后从磁盘加载。
3. **磨损感知偏置**：RAM 内按 128 块（512KB）分区维护写计数
   `[u32; 512]`（数据块直接写 / 元数据 copy-out / 检查点刷盘时累加）；
   分配时在提示位附近扫最多 8 个候选空闲块，选写计数最低分区的块；
   检查点打印统计（总写、最大/最小分区写）便于观测。
4. **日志环分散元数据写**：位图 / inode 表改动先写日志环（J 个块轮转），
   而非固定块。
5. **inode 轮转分配**：inode 散布到全部 8 个表块，避免 inode 表块热点。

> 冷/热数据**动态迁移**（搬移已落盘数据）在无 CoW 的原地更新设计里
> 需要后台垃圾回收/重写机制，风险与复杂度高，本版本不实现；
> 分配侧偏置 + 位图批量刷盘已消除主要热点，迁移列为后续工作（§10）。

## 8. 大文件支持

- size 字段 u64；偏移全程 64 位（AArch64 usize=64，fs_read/fs_write/seek
  已是 64 位）。
- 24 直接 + 单/双/三间接，单文件 ≈4.4TB 上限。
- 稀疏大文件：`fs_read` 对空洞按零填充；`bmap_alloc` 按需分配中间层。
- 测试用稀疏写（seek 到 5GB 写一字节）验证 64 位偏移与多级间接，无需
  真正写 4GB。

## 9. fsync / 同步屏障

- `vfs::fsync(fd)` / `vfs::sync_all()` → `fsops::fs_fsync(dev)` →
  SFS 检查点（§5.4）→ `blkdev::blk_flush(major)`。
- `blk_flush`：virtio-blk 提交 `VIRTIO_BLK_T_FLUSH`（type=4），使 QEMU
  把宿主机页缓存落盘（真机对应 SD/eMMC 的 cache flush）；RAM 磁盘为 no-op。
- linux_compat：`SYS_SYNC / SYS_FSYNC / SYS_FDATASYNC` 从 no-op 改为
  真实调用。

## 10. 已知限制与后续工作

- **块大小 4KB ≠ SD 擦除块（512KB）**：本设计不改块大小（兼容性与改动量
  权衡）。真机上建议：日志区与位图区按擦除块对齐放置（本轮布局已是整块
  对齐），并配合驱动层 discard/TRIM 提示闪存释放块。
- **TRIM/discard 未实现**：virtio-blk 驱动未协商 discard 特性；SD/eMMC
  场景应增加 `VIRTIO_BLK_T_DISCARD` 或等价命令，告知闪存已释放块以
  降低写放大。列为后续工作。
- **冷热数据迁移未实现**（§7）。
- **无锁**：FS 操作仍是单线程模型（SMP 下并发 FS 操作需加锁，属既有问题，
  本轮以全局事务锁缓解日志状态竞争）。
- **日志区写放大**：每事务 2 块/元数据块（头+镜像）。对 10K-100K 次擦写
  寿命的 SD，元数据事务率需 < ~500/s 才不成为瓶颈；正常交互负载远低于此。
- **旧格式不迁移**：v1 魔数不再识别，旧 /data 直接重新 mkfs（开发期可接受；
  生产迁移需 v1→v2 工具）。

## 11. 一致性检查（fsck 语义）

`fs_simple::sfs_check(major)`（供自检与崩溃测试）：

- 超级块魔数/版本/CRC；
- inode 位图 ↔ inode 表：已分配 inode 的 type≠0 且 CRC 有效，inode 0 空闲；
- 数据位图 ↔ inode 块列表：所有 inode 引用的块已分配且 < total；反之
  已分配块必须被某个 inode 引用（否则为孤儿块，报错）；
- 目录项：引用的 ino 已分配、名字合法、目录大小是块大小整数倍；
- root ino==1 且为目录。

返回 0 = 一致，-1 = 发现错误（打印明细）。

## 12. 测试方案

1. **内核自检**（启动时 /tmp 与 /data）：基本读写、截断、改名、符号链接、
   稀疏大文件（5GB 偏移写读）、日志单元路径（构造事务 → 模拟崩溃不
   copy-out → 重新挂载 → 重放验证）。
2. **QEMU 掉电模拟**（`tools/sfs_crash_test.py`）：第一次启动经 UART shell
   向 /data 持续写入带校验的文件，写入中途 `SIGKILL` QEMU（模拟掉电，
   不优雅关机）；第二次启动验证：恢复日志打印、`sfs_check` 全过、
   每个测试文件要么不存在要么内容校验通过（无撕裂）。
3. **一致性校验**：崩溃测试第二轮运行 `sfs_check` 作为通过判据。
4. 构建期：`mkfs_sfs.py` 产出的根镜像可被内核正常挂载（双向格式一致性）。
